the big idea

Search by meaning, not by keyword

A normal search box looks for matching words. If you search "car inventor" but the document says "the automobile was created by," a keyword search finds nothing — even though it's the exact answer.

RAG solves this by converting text into vectors — lists of numbers that represent meaning, not spelling. Similar ideas end up as nearby points in space, even if they don't share a single word. That's the whole trick. Everything below is just the machinery for doing that at scale, reliably, and grounding an AI's answer in real text instead of a guess.

the pipeline

Six steps, start to finish

01

Chunking

Long documents get cut into smaller pieces — a paragraph or a few sentences each — because comparing whole documents for meaning is too blunt an instrument. Smaller pieces let the system point to the exact passage that answers a question.

Like tearing a cookbook into individual recipes instead of searching the whole book at once.
02

Embedding

Each chunk is fed through a small AI model (BAAI/bge-small-en-v1.5) that outputs 384 numbers summarizing what the text means. This list of numbers is called a vector or an embedding.

Like giving every sentence GPS coordinates in "meaning-space" — sentences about similar topics land near each other.
03

Storage

All those vectors — plus the original text they came from — get saved into a vector database (we used ChromaDB). Think of it as a specialized filing cabinet built for one thing: finding the nearest points in a giant space of numbers, fast.

04

Query & retrieval

When you ask a question, it goes through the same embedding model and becomes a vector too. The database then finds which stored chunks are closest to your question's vector — measured by the angle between them, called cosine similarity. Try it below.

05

The guardrail

The database always returns its "closest" matches — even if none of them are actually relevant. So before trusting the result, we check: is the best match's score above a minimum threshold? If not, the system says "I don't know" instead of guessing.

06

Generation

The retrieved chunks get handed to a language model (flan-t5-base) along with your original question, with an instruction to answer using only this text. The model reads the passage and writes a direct answer — grounded in your documents, not invented from thin air.

a real failure we hit

"Who invented the car?"

Our sample database has no chunk about cars. Without a guardrail, here's what happened:

no threshold Retrieval returned the closest available chunk — a paragraph about the Renaissance — because the system always returns something. The generator then latched onto the only "invented by" pattern in that text and confidently answered "Johannes Gutenberg." Wrong, but stated with total confidence.
with threshold The best match's similarity score (0.227) fell below our cutoff (0.3), so the system replied "I don't have information about that in my documents" instead of guessing.

This is why the guardrail step matters as much as retrieval itself — a RAG system that never admits "I don't know" will confidently hallucinate every time its database doesn't cover the question.

glossary

Terms used above

RAG

Retrieval-Augmented Generation — answering questions by first retrieving relevant text, then generating an answer from it, instead of relying purely on what a model memorized during training.

embedding / vector

A list of numbers representing the meaning of a piece of text. Similar meanings produce similar numbers.

chunk

A small piece of a larger document — small enough to embed meaningfully, big enough to contain a complete thought.

vector database

Storage built specifically for finding the nearest vectors to a given point, quickly, even across millions of entries.

cosine similarity

A score from -1 to 1 measuring how closely two vectors point in the same direction. Higher means more similar in meaning.

similarity threshold

A minimum score requirement — if nothing retrieved clears the bar, the system declines to answer rather than guessing.

generation model

The language model that reads retrieved text and writes a natural-language answer grounded in it.
